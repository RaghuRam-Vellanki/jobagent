## What shipped

### 1. Schema + migrations

In `backend/db/models.py`:
- **`CompanyEnrichment`** — per-user cache of LLM-derived metadata (`funding_status`, `size_band`, `valuation`, `confidence`, `source`, timestamps). 30-day TTL enforced at read-time. Indexed by `(user_id, company_name_lc)`.
- **`BriefRun`** — one row per execution. Fields: `platforms` (csv), `jobs_count`, `top_score`, `xlsx_path`, `email_sent`, `email_to`, `error_msg`, timestamps, `duration_ms`. Drives Dashboard "Recent Briefs" widget.
- **3 new Profile columns** — `daily_brief_enabled`, `brief_time` (HH:MM IST), `brief_top_n` (default 30). Added to `_V1_COLUMNS` in `db/database.py` for idempotent ALTER TABLE on existing databases.

### 2. LLM enrichment

In `backend/llm/`:
- **`prompts.py`** — `ENRICHMENT_SYSTEM` forces JSON output with `funding_status` (Bootstrapped|Seed|Series A–D+|Public|Acquired|Subsidiary|Unknown), `size_band` (1-10 through 5001+), `valuation` (string), `confidence` (low|medium|high). + `enrichment_user_prompt(company)`.
- **`claude_client.py`** — new `enrich_company(name, user_id)` method. Uses Haiku, daily-cap check via `_under_daily_cap`, records `LLMCall` row with `purpose="company_enrichment"`. Strips markdown fences, parses JSON, returns dict with sanitized field lengths. Parse failure → `confidence="low"` with "Unknown" fields.

### 3. Brief module (new package)

`backend/brief/`:
- **`enrichment.py`** — `enrich_company(name, user_id)`. Cache-then-LLM: reads `CompanyEnrichment`, returns if within 30-day TTL, else calls `ClaudeClient.enrich_company`, upserts cache. Returns placeholder dict when LLM disabled so the Excel still ships (graceful degradation).
- **`extractor.py`** — regex helpers `parse_salary(jd)` (INR LPA, USD ranges) and `parse_experience(jd)` (X-Y years, X+ years). Used when the scraper didn't extract these.
- **`xlsx_writer.py`** — `write_brief_xlsx(rows, out_path)`. openpyxl. 2 sheets: "Jobs" (12 columns: Source, Company, Title, Location, Experience, Salary, Funding, Size, Valuation, Match Score, Posted, Apply Link as hyperlink; frozen header, auto-filter, conditional color on Match Score) and "Summary" (jobs-per-source counter + timestamp).
- **`orchestrator.py`** — `run_brief(user_id, platforms=None)`. Loads profile, builds `agent_classes` dict (Unstop gated by `persona=="fresher"`, optional agents wrapped in try/except so import errors are non-fatal), runs each source sequentially (safer for 8GB laptop), dedupes by `(company_lower, title_lower)`, scores via `semantic_scorer.score_job`, sorts and takes top-N, enriches companies in parallel via `asyncio.gather`, writes xlsx, calls `send_brief_email`, finalizes `BriefRun` row. Does NOT write to `jobs` table — Brief is read-only on DB.

### 4. Three new discovery agents

- **`agents/hn_whoishiring_agent.py`** — No Playwright, pure httpx. Fetches most recent "Ask HN: Who is hiring?" thread via HN Algolia API, parses each top-level comment using the conventional `Company | Title | Location | URL` pattern, keyword + India-signal filter. ~30 jobs.
- **`agents/wellfound_agent.py`** — Playwright headless against `wellfound.com/jobs?q=&l=`. No login. Scrapes `[data-test=JobSearchCard]` fallbacks. ~20 cards per keyword.
- **`agents/google_jobs_agent.py`** — Playwright headless against `google.com/search?q=<kw>+jobs&ibp=htl;jobs`. Catches postings on smaller company sites missed by LinkedIn/Naukri. ~20 cards.
- **Unstop revived** — existing `unstop_agent.py` re-wired into brief orchestrator (fresher-only).

### 5. Email delivery

In `backend/notifications.py`:
- **`send_brief_email(to, xlsx_path, summary, top5)`** — reuses existing SMTP config (`SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD` etc.). Subject `[JobAgent] Daily Brief — {N} jobs for {YYYY-MM-DD}`. Multipart: plain + HTML (top-5 jobs as a styled table with apply links) + xlsx attachment with proper MIME type. Best-effort: returns False on SMTP error, logs the failure.

### 6. API + scheduler

- **`backend/api/brief.py`** — three endpoints:
  - `POST /api/brief/run` — kicks off brief in a dedicated event-loop thread (ProactorEventLoop on Windows), returns immediately with `queued:true`.
  - `GET /api/brief/history?limit=20` — recent BriefRun rows for the current user.
  - `GET /api/brief/{run_id}/download` — FileResponse of the xlsx (auth-scoped).
- Router registered in `backend/main.py`.
- **`backend/scheduler.py`** — added `_last_brief` tracker dict and a second loop in `_tick()` that fires `_fire_brief(user_id)` when `Profile.daily_brief_enabled` AND now matches `brief_time` AND not already fired today. `_fire_brief` delegates to `api.brief._start_brief_thread` so the brief runs in its own Playwright-compatible event loop.

### 7. Frontend

- **`frontend/src/lib/api.ts`** — `runBrief`, `getBriefHistory`, `downloadBriefUrl` helpers.
- **`frontend/src/pages/Settings.tsx`** — Daily Brief section under "Limits & Delays" tab: toggle, brief-time picker, top-N input, "Send a test brief now" button.
- **`frontend/src/pages/Dashboard.tsx`** — "Run Brief Now" button in the Agent Controls header. "Recent Briefs" widget showing the last 10 runs with email-sent badge and Excel download link.
- **`backend/api/profile.py`** — surfaces the three new Profile columns in GET + accepts them in PUT.

### 8. Dependencies

- `httpx==0.27.2` — HN agent fetcher (most other agents already use it)

## Notes for future sessions

- The Brief uses `match_threshold` from Profile but applies a soft floor of 40 (vs 60 for Apply) — Brief is informational, not load-bearing on the apply queue, so weaker matches are OK to surface.
- Sources run **sequentially** in the orchestrator, not in parallel via `asyncio.gather`. Reason: 8GB laptop + LinkedIn needs a visible browser window. If we ever ship a server-side daemon with more RAM, parallelizing the 3 headless agents (HN/Wellfound/Google) is the obvious next optimization.
- `BriefRun.xlsx_path` is absolute. `GET /{id}/download` checks file existence before streaming — older xlsx files cleaned up manually return 410.
- `agent_classes_for(persona)` in the orchestrator wraps every optional agent in `try/except ImportError` — so a busted Playwright install on, say, Wellfound won't kill the whole brief. Apply flow stays on the strict path.
